# Quazort_Up

**Quazort_Up** — это асинхронный бэкенд-сервис для интерактивного анатомического справочника тренировок. Проект представляет собой демонстрацию работы REST API с разграничением прав доступа - публичный/приватный контент, JWT-авторизацией -Access/Refresh tokens и кэшированием данных.

Основная идея сервиса — поддержка интерактивной 2D карты тела человека (с трех ракурсов), где пользователь может запрашивать упражнения, таргетированно кликая на конкретные группы мышц.

---

##  Технологический стек

* **Framework:** FastAPI (Python 3.12)
* **Database:** PostgreSQL
* **Database Migrations:** Alembic
* **Caching:** Redis
* **Authentication:** JWT (Access & Refresh Tokens)
* **DevOps:** Docker, Docker Compose

---

##  Ролевая модель и логика доступа

В системе реализовано строгое разделение уровней доступа для снижения нагрузки на базу данных и защиты приватного контента:

1. **Гостевой доступ (Без регистрации):**
   * Просмотр базовых советов и рекомендаций по тренировкам.
   * Доступ к интерактивной карте тела.

2. **Авторизованный доступ (JWT):**
   * Полноценный доступ к интерактивной карте. При интеграции с фронтендом, клик по определенной мышце отправляет запрос на бэкенд и возвращает кастомную выборку упражнений именно под эту мышцу.
   * Безопасная аутентификация через связку **Access Token** (короткий срок жизни) + **Refresh Token** (хранится в базе/куках для обновления сессии).

---

##  Архитектура и оптимизация

* **Миграции базы данных:** Архитектура таблиц (пользователи, группы мышц, упражнения) полностью контролируется через **Alembic**, это позволяет гибко обновлять схему PostgreSQL без потери данных.
* **Кэширование данных (Redis):** Список групп мышц и базовые справочные данные кэшируются в Redis. Это исключает повторные тяжелые `SELECT` запросы к PostgreSQL при частых кликах пользователя по мышцам.
* **Docker Compose:** Весь проект (FastAPI, PostgreSQL, Redis) разворачивается одной командой в изолированных контейнерах, соединенных во внутреннюю сеть.
